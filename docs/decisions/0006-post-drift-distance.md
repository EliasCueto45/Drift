# Distance drifted since posting

The post list displays age followed by approximate distance from the original posting spot to the latest tracked anchor. This is horizontal WGS84 geodesic displacement, not accumulated path length, viewer distance or distance since the cloud was first detected. A cloud that returns toward its starting point can have a smaller displacement. Tracking accuracy and observation age limit precision.

The server saves `initial_anchor` privately in the message document at creation. Worker updates continue changing the existing current anchor and cloud ID. Merge/split transfers keep the same message and initial anchor; no worker request or tracking schema change is needed. Public serialization computes optional `Message.driftDistanceM` from these two coordinates with the existing PyProj geodesic utility. Initial responses return zero, including anonymous posts; retry receipts return current serialized data. Tracking duplicates, held content, rollback and cleanup retain their existing semantics. Views perform no extra satellite calls, history scans, writes or database queries for this value.

New fixture seeding also saves known original anchors; existing seeded/live documents without a baseline return null. Do not backfill an unknown original position from a moved current position. Old consumers may ignore the optional field, and new UI handles absent/null fields as “drift distance unavailable.” Known distances appear directly beside age: `9 min ago · drifted from 5 km away`. The original coordinate is not exposed as a separate public field. It expires/deletes with the whole message document through normal cleanup, requiring no new collection or index.

The display rounds coarsely and labels drift as approximate. It follows the latest stored tracking update and stops changing when observations stop; browser wall time never multiplies wind into fabricated distance. The same PostItem metadata appears in preview panels and expanded cloud lists.
