# Anonymous posting and local-day streaks

People may publish messages and create clouds without registering. A server-issued anonymous browser session owns those posts/clouds and may delete only its own content. Public names are **Anonymous**. Anonymous principals are opaque random IDs, not Clerk IDs; no email, name, device fingerprint or location trail is collected for this feature. This is pseudonymous browser ownership, not a promise that posts cannot be linked by their public author ID. Voting and media-upload authorization still require Clerk. Invalid Clerk/worker bearer tokens must never silently become guest credentials.

`POST /api/v1/session/anonymous` accepts `{}` and issues/renews a 180-day random credential in an HttpOnly, SameSite=Lax cookie scoped to `/api`. HTTPS deployments also set Secure. MongoDB retains only its SHA-256 hash and opaque principal ID. The response exposes the session's public ID/name, not the token. `GET` on the same route restores a valid existing session or returns null. Session issuance and posting remain rate-limited. Clearing cookies, using another browser/domain or expiry loses anonymous ownership/streak continuity; registering does not silently merge or de-anonymize earlier posts.

`GET /api/v1/me/streak` returns the caller's private `PostingStreak`. The browser sends `X-Drift-Time-Zone` with its IANA zone. The server validates and pins that zone on first initialization; unknown legacy callers default to UTC. Subsequent device time-zone headers do not manufacture extra days. Travel/time-zone changes need a separately reviewed account-setting policy. The UI displays the actual counting zone and next midnight.

Only a successfully committed new message counts. All kinds count once per day toward consecutive posting days; multiple posts increment total posts but not streak days. Missing a full local day resets the current streak; longest streak remains. UTC receipt time comes from the server, independently of replay/observation clocks and submitted timestamps. Daylight-saving changes use IANA calendar dates and next local midnight. Deleting/expiring a post does not undo a completed posting day. Idempotent retries and worker movement/replay never award a second post/day. Guest streak aggregates expire after inactivity; Clerk aggregates remain tied to the account.

The on-device indoor/outdoor classifier controls cloud rendering; it does not provide trusted server-side proof. These are **posting streaks**, not verified outdoor streaks. No client-provided outdoor flag awards credit. Requiring trusted outdoor proof later needs an agreed server-side verification interface and retention policy.

Canonical schema receives new `PostingStreak`/response and `AnonymousSession`/response definitions; existing message/cloud payloads retain their shape. The identity-authority rule now permits server-issued anonymous posting sessions in addition to verified Clerk users. Owner 1/4 should review the guest UI and deployment cookie/origin behavior; the Next proxy must forward cookies and Set-Cookie under the same public origin.
