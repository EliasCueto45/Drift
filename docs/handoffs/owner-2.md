# Owner 2 — Remaining integration work

- **Anonymous/streak browser acceptance (Owners 1/2/4):** verify anonymous post/cloud creation, reload, ownership deletion and local-midnight streak display through the deployed Next proxy on phones. Check HttpOnly/Secure cookie delivery and separate Clerk/guest identities. Travel-time-zone changes and guest-to-account migration are intentionally not implemented. The current on-device classifier supplies rendering hints; trusted outdoor eligibility would need a server verification contract before gating streaks.

- **Browser Clerk acceptance (Owners 1/2/4):** configure `DRIFT_APP_ORIGIN` to the actual browser/tunnel origin and the UI dataset to the provisioned live dataset. Verify two real Clerk users can create/delete clouds, post/delete messages, vote/unvote, see public authors and fail unauthorized mutations. Repeat with a lost response, reload and moving/retired clouds. Component/API tests do not establish real browser acceptance.
- **Private media (Owners 1/2/4):** connect the image composer/upload/playback UI to existing media endpoints and configure a real private S3-compatible bucket, CORS, credentials and noncurrent-object lifecycle. Run actual browser upload/completion/playback/deletion checks. Atlas persists metadata; S3 stores media bytes.
- **Deployment and scheduling (Owner 4):** deploy the Python API and tracking worker, supervise `python -m drift_api.cli cleanup --watch` or schedule one-shot cleanup every five minutes, monitor deletion backlog and document Atlas/object-store backup retention and network access. CI configuration still needs a GitHub run and Linux verification after review.
- **Shared interfaces (Owners 1/4):** add response schemas for `GET /api/v1/assets/:id/url` and `GET /api/v1/messages/:id/artwork`; confirm normalized drawing polylines. Define selected/manual caller-location transport for the 50 km creation-radius check without breaking v1 consumers.
- **Phone AR validation (Owners 1/2/3/4):** validate current camera/map projection and new map-outline creation on actual phones, including denied permissions, keyboard access and two separated viewpoints. Consume altitude provenance accurately. Generic links beyond the existing song-host allowlist or removal/renaming of media kinds need a reviewed compatibility plan. Browser camera frames must stay on the device.
- **Live browser acceptance (all owners):** provision a separate live dataset/run, configure matching worker secret and API URL, publish current NOAA observations, and verify observation age/current geometry in the browser. Keep live and replay clocks/journals separate.
